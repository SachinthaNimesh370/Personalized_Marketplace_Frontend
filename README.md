# PrimeMarket.lk - Personalized Marketplace Frontend

A React + Vite single-page application built for the **PrimeMarket.lk Personalized Marketplace Feed** technical assessment. It delivers an interactive property and vehicle browsing experience driven by real-time ranking algorithms, session persistence, and private AWS S3 media integration.

---

## 1. Features Overview

- **User Switcher & Persistent Sessions**:
  - Quickly toggle between predefined test personas (`user_a` - Nimal, `user_b` - Kasun).
  - Selected user ID persists in `localStorage`. Even across fresh browser tabs or incognito sessions, the user profile is remembered, and the server fetches their specific interaction history from MongoDB Atlas.
- **Dynamic Personalized Feed**:
  - Renders the top 20 recommendations sorted by affinity score.
  - Category filter tabs (**All**, **🚗 Vehicles**, **🏡 Properties**).
  - Category-specific attributes (make, model, year for vehicles; property type, bedrooms, land size for properties).
- **"Why Recommended" Explanations**:
  - Transparent recommendation tags on each listing card (e.g., *"You like vehicle listings"*, *"Similar to Toyota you showed interest in"*, *"Matches your interest in Colombo"*).
- **Cold-Start Indicator Banner**:
  - Clearly alerts graders and users when a new persona with no prior history is browsing a balanced, popularity-ranked cold feed.
- **Interactive Action System**:
  - **👁 View Details**: Opens a detailed modal dialog and logs an intentional `view` event (anti-spam design avoids logging views on passive page renders).
  - **⭐ Save Listing**: Records a `save` event (weight: 4.0), gives instant toast feedback, and removes the item from future recommendation candidates.
  - **💬 Contact Seller**: Records a `contact` event (weight: 8.0) representing highest user intent.
- **Real-Time Activity Drawer**:
  - Floating expandable drawer in the bottom right corner showing the exact append-only interaction history stored in MongoDB Atlas for the active user.
- **Private S3 Image Rendering**:
  - Renders secure 5-minute presigned URLs generated by the backend for private S3 images, with graceful fallbacks.

## 3. Quick Start & Setup

### Prerequisites
- Node.js (v18+)
- Backend running on `http://localhost:5000` (refer to `Personalized_Marketplace_Backend/README.md`)

### Installation & Environment Configuration
```bash
# Navigate to the frontend directory
cd Personalized_Marketplace_Frontend

# Install dependencies
npm install

# Copy environment template
cp .env.example .env
```

Ensure your `.env` contains:
```env
VITE_API_URL=http://localhost:5000
```
*(Note: A development proxy is also preconfigured in `vite.config.js` routing `/api` and `/static` to `http://localhost:5000`).*

### Running Locally
```bash
# Start Vite development server on http://localhost:5173
npm run dev
```

### Production Build
```bash
# Compile and validate production bundle
npm run build
```

## 4. How to Test & Demo the Application

### A. Testing Cold Start
1. Select **User A (Nimal)** or **User B (Kasun)**.
2. If the user has no recorded interactions, a **"Cold Start Mode Active"** banner appears.
3. Listings will be sorted strictly by baseline popularity, interleaved between properties and vehicles, with the reason `"Popular right now"`.

### B. Testing Personalization & User Isolation
1. Select **User A (Nimal)**:
   - Click **Save** on a vehicle (e.g., Toyota Aqua).
   - Click **Contact Seller** on another vehicle.
   - Click **View** on a third vehicle to inspect its modal.
   - Observe the feed immediately re-ranks: vehicle listings (especially Toyota/Honda) move to the very top with reasons like *"You like vehicle listings"* and *"Similar to Toyota you showed interest in"*.
2. Switch to **User B (Kasun)**:
   - Notice User B's feed remains completely unaffected by User A's activity.
   - Interact with properties (e.g., Save a Luxury Apartment).
   - User B's feed will prioritize properties, proving strict user isolation.

### C. Testing Session Persistence Across Fresh Browser Windows
1. Make several interactions as User A.
2. Open a **new Incognito window** or a completely fresh browser session.
3. Open `http://localhost:5173`.
4. User A's session and past activity are preserved via `localStorage` and MongoDB Atlas. The server returns the exact personalized feed reflecting past actions.

### D. Testing Repeat Handling & Anti-Spam
1. Open the detailed view for an item multiple times.
2. Notice that repeated views apply diminishing logarithmic returns and a viewed demotion penalty (`VIEWED_PENALTY = 0.3`), ensuring fresh relevant listings always rank ahead of spammed items.
3. Contacted listings are completely excluded from the recommendation feed because the intent was completed.

### E. Inspecting MongoDB Atlas Activity History
1. Click the **"📊 View Activity Log"** button in the bottom right corner.
2. Inspect the real-time interaction events saved in MongoDB Atlas for the currently selected user.

## 5. UI & Accessibility Considerations

- **Semantic HTML**: Standard header, main, and footer semantics with unique descriptive IDs and accessible aria-labels.
- **Optimized Interactions**: Action buttons disable temporarily during async API submission to prevent double-click race conditions.
- **No Heavy UI Frameworks**: Built cleanly with Vanilla CSS for zero bundle bloat and maximum rendering speed.
